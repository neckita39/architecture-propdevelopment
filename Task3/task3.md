### Диаграмма контейнеров

Всё новое взаимодействие на схеме обозначено красным для наглядности.

На схему добавлено мобильное приложение mobile-app. Далее оно запрашивает токен у auth-service-1,
и с этим токеном идет к tenant-core-app, который инициирует вызов API партнера.
Все запросы проходят через firewall.
Простым решением с точки зрения отказоустойчивости будет инициация запроса к партнеру, который ставит
наш запрос в свою внутреннюю очередь. Затем, по средствам вебхука, он обращается к tenant-core-app, чтобы сообщить
о результате операции. tenant-core-app через WebSocket сообщает mobile-app о результате.
Важно отметить, что webhook используется лишь для информирования о результате, так как открывает домофон API партнера

### Список требований


Безопасность:
* Передача данных по HTTPS (TLS).
* Шифрование биометрических данных и номеров при хранении и передаче
* Доступ к API партнёра — только с белого листа ip-адресов
* Логгирование действий

Аутентификация и авторизация:
* Протокол OAuth 2.0
* Все обращения к API защищены токеном доступа
* Валидация токена по истечению и подписи.

Взаимодействие между системами:
* Собственник -> mobile-app: Запрос на открытие двери
* mobile-app -> auth-service-1: Запрос на получение токена
* auth-service-1 -> mobile-app: Ответ с токеном
* mobile-app -> tenant-core-app: Запрос с токеном на совершение действия
* tenant-core-app -> API Умный Дом: Запрос на осуществление действия
* API Умный Дом -> tenant-core-app: Результат действия
* tenant-core-app -> mobile-app: Пуш с результатом
